# Writing Rules

Scope: all prose, including messages, documentation, commit bodies and pull request descriptions. Apply root artifact-specific rules first.

## Style

- US English; no US idioms or colloquialisms.
- No em dashes. Rewrite sentence structure; do not substitute punctuation.
- Keep register consistent; do not switch from opening fragments to full sentences.
- Expand acronyms/jargon on first use.

## Density

- Remove filler, hedges, throat-clearing, repeated points and empty intensifiers.
- Preserve necessary transitions/connectives; avoid terse, choppy sentences.
- Do not repeat an already-clear subject.
- Prefer stronger, precise wording.

## Structure

- Prose paragraphs: 2–3 sentences, naturally varied lengths; 1 purpose, at most 2.
- Parallel items, procedures, constraints: lists. Connected reasoning: prose.
- Section boundaries: Markdown headings, never bold text or bullets.
- No bold emphasis, horizontal rules or hashtags.

## Content

- State only provided/verified facts, figures and details.
- State issues plainly; no editorializing, soft closers or persuasion.
- Editing: preserve word choices/voice; fix only defects.
- Requested deletion: remove without replacement filler.
- Pull request descriptions: change, reason, validation, known risks.
